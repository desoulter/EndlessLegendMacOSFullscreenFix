# Сравнение нагрузки GPU с fullscreen-патчем и без него

Логгер записывает показатели во время обычного запуска игры. Игру запускаете и
закрываете вручную; утилита не управляет ею, не внедряет код и не меняет патч,
графические настройки или управление вентиляторами.

Сборщик рассчитан на Apple Silicon и использует Python 3.9+, Apple Command Line
Tools и системные API macOS. Дополнительные пакеты Python не нужны. При первом
запуске `tools/telemetry.m` компилируется в отдельную утилиту ARM64.

## Что записывается

- Раз в секунду: загрузка всего GPU, Renderer/Tiler utilization и используемая им память.
- Средняя и максимальная температура доступных SMC-датчиков GPU `Tg*`, а также CPU
  `Te*`/`Tp*`/`Ts*`. Значение каждого датчика сохраняется отдельно в JSON.
- Обороты вентиляторов `F0Ac`/`F1Ac` и системное состояние thermal pressure.
- Наличие процесса игры, активность её окна, CPU процесса и используемая им память,
  когда macOS разрешает их чтение. 100% CPU означает одно полностью занятое ядро.
- Источник питания; размеры и частота текущего режима дисплея, если API их выдаёт.
  Для переменной частоты macOS может не сообщать конкретное значение в герцах.
- Состояние установки патча, контрольные суммы, настройки видео в начале и конце
  прогона, системная конфигурация энергосбережения и фактические времена замеров.
- По флагу `--power`: оценочная мощность GPU/CPU, частота активного GPU и active
  residency из `powermetrics`. Его исходный вывод также сохраняется.

Нагрузка GPU, температура, вентиляторы и мощность относятся ко всему компьютеру.
Это не отдельный счётчик только Endless Legend. Закройте другие приложения,
нагружающие GPU. У разных программ мониторинга могут отличаться выбранные датчики
и способ усреднения: корректнее сравнивать два прогона одного логгера, а не
максимум из него со средним значением iStat.

Обычный логгер FPS не измеряет. Для временного наблюдателя частоты present,
фактических буферов и MSAA используйте [диагностику рендеринга](RENDER-DIAGNOSTICS.ru.md).
Сами показатели нагрузки и нагрева не доказывают, что причина — именно FPS,
MSAA или Retina.

## 1. Проверить доступ к датчикам

Все команды ниже выполняются в обычном Terminal **из каталога репозитория**:

```sh
python3 tools/gpu_benchmark.py doctor
```

В конце должно появиться `READY`. Проверка показывает доступные датчики и текущие
значения. Нужны как загрузка GPU, так и температура. Недоступные данные обозначаются
`null` или пустой ячейкой CSV; отсутствующая температура не заменяется нулём.

Если чтение SMC запрещено и в обычном Terminal:

```sh
sudo -v
python3 tools/gpu_benchmark.py doctor --sudo-sensors
```

Тогда добавляйте `--sudo-sensors` и к командам `record`. С правами администратора
запускается только нативный сборщик. Пароль вводится в Terminal, утилита его не
читает и не сохраняет. Автоматизированные песочницы могут блокировать SMC и
получение списка процессов даже при доступном счётчике загрузки GPU.

## 2. Подготовить одинаковые условия

1. Для обоих запусков используйте одно питание — желательно подключённый адаптер,
   одинаковый режим энергопотребления, монитор и частоту экрана.
2. Не меняйте разрешение, качество, VSync и большой интерфейс между прогонами.
3. До каждого запуска дайте ноутбуку остыть примерно до одной начальной температуры
   и сходных оборотов вентиляторов. Пять минут ожидания сами по себе этого не гарантируют.
4. После запуска логгера оставьте 30–60 секунд простоя, затем запускайте игру.
5. Начните тот же туториал, выполняйте одинаковые действия и сравнивайте одинаковые
   временные участки. Для более строгого сравнения после одинакового шага оставьте
   одну сцену и камеру неподвижными на 5–10 минут. Случайное прохождение измеряет
   одновременно различия патча и различия действий.

## 3. Прогон с патчем

Сначала проверьте, что fullscreen-патч установлен. Логгер его не устанавливает:

```sh
python3 fullscreen_fix.py status
```

Желательный вариант с мощностью в ваттах:

```sh
sudo -v
python3 tools/gpu_benchmark.py record --label patched --power
```

`powermetrics` требует прав администратора. Без них можно записать загрузку,
температуру и вентиляторы, убрав `--power`:

```sh
python3 tools/gpu_benchmark.py record --label patched
```

Запустите игру вручную, пройдите выбранный сценарий и выйдите из игры.
Логгер автоматически определит запуск/закрытие и завершится через 15 секунд после
выхода, сохранив небольшой участок остывания. Либо остановите его `Ctrl+C`.
По умолчанию запись ограничена 20 минутами; другой предел в секундах задаётся
через `--duration 1800`. Если нужно продолжать после закрытия игры, используйте
`--keep-running`.

Запускайте логгер до игры: время первого обнаружения процесса используется для
совмещения прогонов. Если процесс игры не обнаружен, запись это явно сообщает,
а команда сравнения не принимает её за игровой прогон.

## 4. Прогон без патча

Закройте игру, удалите только fullscreen-патч и дайте компьютеру остыть:

```sh
python3 fullscreen_fix.py uninstall
```

Повторите те же условия и последовательность действий:

```sh
sudo -v
python3 tools/gpu_benchmark.py record --label original --power
```

Для сопоставимого набора данных используйте `--power` в обоих прогонах или в обоих
обходитесь без него. Метки `patched`/`original` проверяются по фактическому состоянию
игровых файлов: если они не совпадают, запись не начинается.

Исправления звука и шейдеров следует оставить одинаковыми в обоих прогонах.
Логгер не удаляет их и не выполняет проверку файлов Steam.

## 5. Сравнить

Для последних успешно завершённых игровых прогонов с метками `patched` и `original`:

```sh
python3 tools/gpu_benchmark.py compare
```

Результат: `benchmark-results/comparison.html` и `comparison.json`. Откройте HTML
обычным браузером. Он работает без интернета, содержит графики двух прогонов,
средние/максимальные значения, разницу средних и условия записи. Можно выбрать
диапазон времени после запуска игры и включить/исключить периоды игры в фоне.
По умолчанию берётся общий по длительности участок двух прогонов.

Например, сравнить от двух до десяти минут после запуска игры:

```sh
python3 tools/gpu_benchmark.py compare --start 120 --end 600
```

Если предыдущий отчёт уже существует, выберите новый путь: существующие отчёты
и папки прогонов не перезаписываются.

```sh
python3 tools/gpu_benchmark.py compare --start 120 --end 600 --output benchmark-results/tutorial-comparison.html
```

Можно явно передать две папки вместо автоматического выбора последних прогонов:

```sh
python3 tools/gpu_benchmark.py compare benchmark-results/patched-ДАТА-ВРЕМЯ benchmark-results/original-ДАТА-ВРЕМЯ --output benchmark-results/comparison-2.html
```

Для более надёжного вывода повторите в порядке **патч → оригинал → оригинал → патч**
с остыванием между запусками. Сравнивайте также начальную температуру, фактический
участок сценария и число доступных замеров, а не только максимальную температуру.

## Состав папки прогона

| Файл | Содержимое |
| --- | --- |
| `samples.csv` | Основные показатели с UTC-временем, временем от старта записи и игры |
| `samples.jsonl` | Те же замеры, все отдельные датчики и детали времени сбора |
| `metadata.json` | Настройки, состояние патча, доступность датчиков и результат записи |
| `events.jsonl` | Запуск/закрытие игры и логгера |
| `telemetry.stderr.txt` | Ошибки нативного сборщика |
| `powermetrics.txt`, `power.jsonl` | Исходная и разобранная мощность, если включён `--power` |
| `powermetrics.stderr.txt` | Ошибки привилегированного сборщика мощности |

`powermetrics` и нативный сборщик опрашиваются независимо. Возраст использованного
замера мощности записывается как `power_age_s`; слишком старые значения не
подставляются в новые строки. Разрывы в графиках не заполняются выдуманными данными.
Результаты сохраняются локально, исключены из Git и никуда автоматически не отправляются.

`collection_ms` показывает затраты времени нативного сбора. Сам логгер не рисует
окно мониторинга и не выполняет графический бенчмарк параллельно игре.

## Источники интерфейсов

- `powermetrics --help` на тестируемом Mac: доступные samplers и единицы мощности.
- [macmon: SMC и системные источники](https://github.com/vladkens/macmon/blob/main/src/sources.rs):
  проверка структуры AppleSMC и выбора `AppleSMCKeysEndpoint`.
- [macmon: группировка датчиков](https://github.com/vladkens/macmon/blob/main/src/metrics.rs):
  температурные группы `Tg*`, `Tp*`, `Te*`, `Ts*`.

SMC и AGX-счётчики — аппаратно-зависимые интерфейсы macOS. Команда `doctor`
проверяет их доступность на конкретном компьютере.
