# Сравнение записей туториала — 7 ноября 2026

Источник: `benchmark-results/original-probe-tutorial-20261107-004237/` и
`benchmark-results/patched-probe-tutorial-20261107-004929/`. В обоих случаях
полные 180 секунд после отметки F8 и 30 секунд стабилизации, по 180 активных
замеров; ошибок выделения framebuffer нет. Наблюдатель не ограничивал FPS.

| Среднее за отмеченное окно | Original | Patched |
| --- | ---: | ---: |
| GPU, Вт | 6,192 | 14,266 |
| CPU, Вт | 6,004 | 5,494 |
| Завершённые present, кадров/с | 71,859 | 101,746 |
| Активная частота GPU, МГц | 888,961 | 1305,822 |
| GPU utilization, % | 77,900 | 78,522 |
| Самый горячий GPU-датчик, °C | 84,130 | 95,428 |
| Вентиляторы, об/мин | 3277 / 3538 | 4374 / 4721 |

В обоих случаях рендер фактически 2048×1330, MSAA сцены 4×, VSyncCount=1,
OpenGL swap interval=1, вычисленный Unity targetFrameRate=120. Значение
TargetFrameRate=100 в Registry.xml не становится действующим пределом при VSync.
Питание в обоих случаях от батареи, powermode=0, игра активна всё окно.

Original рисует в multisampled framebuffer 0 размером 2048×1330. Patched рисует
в промежуточный MSAA framebuffer 2048×1330 с 4 samples и выводит результат в
viewport 3024×1890; поверхность вывода single-sample. Вся сцена не становится
3024×1890. Максимальная температура совпадает с максимумом семи общих Tg-датчиков
в каждом замере; наборы остальных температурных датчиков отличаются.

Расход GPU выше в 2,304 раза, а present чаще в 1,416 раза. Повышенная частота
кадров и GPU — конкретный кандидат для снижения потребления. Это не изолированная
оценка стоимости масштабирования: частота кадров и действия в сцене различались.

В сохранённых Diagnostics оба запуска загружают `Tutorial - Chapter 1.zip` и
переходят в WorldView до отметки. Во время окна были события CityWorkersPanel,
удаления проекта колониста и перехода следующего хода. Переход произошёл примерно
на 137,7 секунде измерения original и 111,0 секунде patched. Поэтому средние выше
описывают эти прогоны, а точную цену одного кадра при одинаковой камере не доказывают.

Контрольный протокол использует один шаг туториала, неподвижную камеру и
одинаковые подсказки, без завершения хода. В обоих режимах заданы
`--fps-cap 60 --measure 180`, одинаковые разрешение и MSAA.
Явное ограничение FPS наблюдателя ожидает после
swap и учитывает уже потраченное на VSync время. Нативный тест с имитацией
120-герцового swap проверяет, что предел не превращается примерно в 40 кадров/с.
Изменений production-helper в этой проверке нет.

Самостоятельный HTML-отчёт: `benchmark-results/tutorial-comparison-20261107.html`.

## Неподвижная сцена с ограничением 60 — контрольные прогоны

Источник: `original-probe-fps60-tutorial-20261107-134304` и
`patched-probe-fps60-tutorial-20261107-134950`. По 180 активных замеров после F8
и стабилизации. В обоих прогонах выбран один шаг туториала с примерно одинаковым
положением камеры. В Diagnostics нет событий смены шага/хода внутри обоих окон. Рендер
2048×1330, MSAA 4×, питание от батареи и powermode=0 совпадают. Ошибок буферов нет.

| Среднее за отмеченное окно | Original | Patched |
| --- | ---: | ---: |
| GPU, Вт | 3,483 | 3,427 |
| CPU, Вт, вся система | 5,065 | 2,328 |
| Завершённые present, кадров/с | 54,135 | 53,044 |
| Активная частота GPU, МГц | 462,911 | 485,972 |
| Самый горячий GPU-датчик, °C | 72,787 | 66,813 |
| Вентиляторы, об/мин | 2316 / 2502 | 2317 / 2502 |

В этом сценарии крупного дополнительного расхода GPU у patched нет: разница
мощности −1,63% при разнице частоты present −2,02%. Точное равенство стоимости
одного кадра не устанавливается: камеры приблизительно совпадают, а системные
показатели включают другие процессы. Сравнение одинаковых семи Tg-датчиков
подтверждает температуру; каждый записанный максимум совпадает с их максимумом.

Практический результат: явное ограничение частоты сохраняет выбранное разрешение
и MSAA, а в контрольной сцене оба режима дают около 3,4–3,5 Вт GPU и минимальные
обороты вентиляторов. Фактическая частота при заданной верхней границе 60 составила
53–54 present/с. Это не обещание точных 60 кадров/с во всех сценах.

Более низкая температура patched согласуется и с меньшей общей мощностью CPU
в этом прогоне, однако сама разница CPU не приписывается исключительно патчу.
Предыдущие записи без ограничения содержали действия в туториале, поэтому
разницу с ними нельзя целиком считать чистым эффектом ограничения кадров.

Проверенная политика ожидания после swap перенесена в production-helper как
необязательная настройка `ContextFix/runtime-options.json`, по умолчанию выключена.
Готовая команда для целой существующей установки:

```sh
python3 fullscreen_fix.py update --fps-cap 60
```

Нативные тесты проверяют чтение опций из .app, работу ограничителя отдельно и
вместе с наблюдателем, без удвоения паузы. Автоматические тесты установщика
проверяют, что update меняет только helper/manifest/опции и откатывает их при
ошибке записи. Обычный запуск через Steam с ограничителем без диагностического
наблюдателя также проверен на конфигурации, указанной в README.

HTML-отчёт: `benchmark-results/tutorial-fps60-comparison-20261107.html`.
